## 1. 实现 MeasurementTransport（主线唯一要写的类）

```cpp
struct WasapiMeasureTransport : rta::dsp::MeasurementTransport {
    std::vector<double> play_and_capture(const std::vector<double>& out,
                                         size_t samplesToCapture) override;
};
```

契约与注意（每条都有理由，别省）：

1. **播放的必须是传入的同一份序列**。`out` 已含测量电平（`10^(sweepLevelDbfs/20)·sweep`）。
   反卷积参考就是这份序列（C1 `generate_sweep` 注释的硬要求）：若播放端想另加淡入淡出/
   限幅/电平，等于改了参考，恢复的 IR 不再是房间响应。要防点击起振，请改
   `MeasurementSession` 构造里的 `sweepLevelDbfs`（电平会自动抵消），**不要**在传输层动序列。
2. **返回样本数 ≥ samplesToCapture**（扫频 + 1 s）。提前返回会被会话判该声道
   「采集样本不足 → 无效」，`build_corrections` 会因此拒绝整批。
3. **播放与采集必须同步启停、同一 fs**（= SweepSpec.fs）。建议设备独占打开，
   fs 直接设为会话 fs；共享模式下系统混音器/EQ/响度处理会污染测量路径，必须旁路。
4. **采集端点**：话筒输入（真实房间测量）。`wasapi_capture` 已有的采集路径可复用；
   loopback 端点只能测"电一电"链路，测不了房间，不要混用。
5. 采样格式建议 float32 直通；若设备只有 int16，转换后再返回 double，
   并把转换量化噪声算进 SNR 预期（int16 理论上限 ~98 dB，足够 20 dB 门限）。

## 2. 出声授权流程（铁律 1，硬性）

真实测量的扫频是**可闻的**（默认 −20 dBFS，10 s/声道）。主线上必须：

1. 第一次 `play_and_capture` 之前弹横幅，写明：
   - 目标播放设备名 + 采集设备名；
   - 总时长 ≈ 声道数 ×（扫频时长 + 1 s），如 2.0 布局 10 s 扫频 ≈ 22 s；
   - 电平 sweepLevelDbfs（默认 −20 dBFS，向导可给"安静房间/吵闹房间"两档）；
   - **独占模式会静音系统其他声音**。
2. 用户确认后才开始 `run()`。取消（确认框/ESC）= 不调 run()。
3. 建议的两段式：先用 `sweepLevelDbfs = -60` 走一遍完整 run()（不可听，验证链路：
   采集非全零、SNR 门限能触发、进度/取消正常），再请用户授权正式电平重测。
   −60 dBFS 那遍的 SNR 告警是预期的，UI 文案要说明这是链路自检不是失败。
4. `--analyze` 式离线验证（本包 tests/test_room_measurement.cpp 的虚拟房间）已经
   全流程覆盖算法层；主线的第一优先级是把授权流程做对，而不是急着真测。

## 3. 线程模型（仿 knowledge job）

- `run()` 放**后台线程**：每声道一次 10~20 s 的阻塞播放采集，绝不能占 UI 线程。
- `cancelled`：UI 的"停止"按钮只置一个原子 bool，`cancelled` lambda 读它。
  会话在**每个声道开始前**检查（声道内不可中断——传输层自己保证可停，建议
  在 play_and_capture 内部分段喂设备时顺带检查同一个 bool）。
- `onProgress(step, total, channelName)` 从工作线程回调：不要直接摸 UI，
  PostMessage / 投队列到 UI 线程刷新进度条（step 从 1 起，total = 声道数）。
- 参考主线 knowledge job 的"后台线程 + 轮询 + 完成事件"骨架，不新造并发原语。

## 4. 结果 → UI 文案

| 字段 | 建议 UI 行为 |
|---|---|
| `channels[i].peakMs` | 显示"直达声 xx ms"；**SNR 告警在场时不可信**（低信噪比下峰可能被噪声尖峰俘获，实测见 WIP-C2 §3），先提示重测 |
| `warnings` | 逐条原样显示（已是人话，含声道名与建议动作） |
| `aborted` | 显示"已取消"；**禁用"生成校正"按钮**（会话层不拦 aborted 的半套结果，UI 必须拦） |
| 声道 `valid=false` | `note` 里有结构失败原因（采集不足/反卷积失败）；`build_corrections` 会拒绝整批 |
| `subAlign` | 有超低时显示"超低延迟 xx ms / 增益 xx dB"；极性告警在场时先让用户处理接线再重测 |

## 5. CorrectionSet 进现有管线

1. **每声道 IR**：`correctionIrs[i]` → `cfg.channel[c].ir`（按声道 IR 已支持）。
   taps 8192 @48 kHz ≈ 171 ms，与现有卷积器预算一致。
2. **超低增益**：`subGainDb` → 该声道现有 `gainDb`（正值 = 超低偏安静需补增益）。
3. **超低延迟**：`subDelaySamples`（正 = 超低更晚）两种做法：
   - **推荐：IR 前置零填充**——把 N = round(subDelaySamples) 个零插在超低声道 IR 头部，
     延迟进 IR 自包含，管线零改动、导出的 WAV 也带着延迟，任何加载方结果一致；
   - 备选：管线现有 delaySamples 机制（省 taps，但多一个时间轴状态要维护）。
   48 kHz 下 12 ms = 576 样本 ≪ 8192 taps，零填充无预算问题。
4. **globalGainDb**：向导的"整体电平"微调已线性乘进每条 IR，管线无需再处理。
5. **fs/taps** 就地记录在 CorrectionSet 里，写配置时如实带上。

## 6. WAV 导出（存档 / REW 对照）

`export_corrections_wav(cs, dirPrefix)` 每声道写一个 32-bit float 单声道 WAV
（规范 44 字节头自写，tag=3）。注意：**窄字符 fopen 不认 UTF-8 路径**，中文目录请
主线用 `_wfopen + widen` 的现成包装另存（或传 ASCII 路径）；C2 不 include src/audio
正是为了不把 widen 拖进纯算法层。返回空串 = 全部成功，非空 = 第一条错误描述。
