# chipwrap 滚动条占位与 web 一致（1.1.7.75）

> 收口《已知偏差》台账里的「chipwrap 1pt 级宽度差」条目。

## 1. 上游真值

`src/net/ui_page.h` 的 `.npchipwrap` 是普通 `overflow:auto` 容器：

- **内容溢出**：经典滚动条占位约 11pt ⟹ 卡宽 = wrapW − 11；
- **内容不溢出**：不出现滚动条 ⟹ 卡宽 = wrapW。

实测基准（ego/Chromium）记在判据注释里：溢出时首张 `.npchip` 宽 = wrapW−11、6pt 拇指位于 x ∈ [W−8, W−2]、
与卡片右缘间隙约 3pt。

## 2. 原生旧行为（缺陷）

```objc
const CGFloat cardW = MAX(40, W - 11);   // 无条件
```

原生 `.npchipwrap` 是自绘滚动容器（`RLPRailWrapView`），滚动条**始终**占位 11pt，
于是**短列表**（内容放得下、web 根本不会有滚动条）也空出一条 11pt 的槽 —— 这就是偏差台账里那条
「chipwrap 1pt 级宽度差」的真实来源（不是 1pt，是**整条 11pt 槽在不该有的时候存在**）。

## 3. 实现：两遍排版（与浏览器同序）

| 步骤 | 行为 |
|---|---|
| 第 1 遍 | 按 `wrapW` 排一次，得到内容高度 `hWide` |
| 判定 | `hWide <= wrapH + 0.5` ⟹ 放得下 ⟹ **采用 wrapW**，结束 |
| 第 2 遍 | 放不下 ⟹ 按 `wrapW − 11` 重排（此时才真的需要沟槽） |

抽出 `-railLayoutChipsWithWidth:height:` 返回内容高度，`-railLayoutChips` 只做两遍调度与判定。

## 4. 判据改动（3 处，逐条说明理由）

| 判据 | 改动 |
|---|---|
| 「卡宽 = wrapW−11」 | → 「卡宽与溢出状态**自洽**」：由实际 `contentHeight` 决定期望值（溢出 ⟹ W−11，不溢出 ⟹ W）。**旧码在本夹具下会失败**（夹具内容放得下却按 W−11 排），所以这条仍有回归价值 |
| 「拇指与卡片右缘 ~3pt」 | 基准由「当前卡片实测右缘」改为「web 的 11pt 沟槽起点 W−11」。原因：该块为量拇指**人为**把 `contentHeight` 设成 1200，而卡片宽度是按真实溢出状态算的，夹具里两者本就不一致；用 W−11 才是这条判据本来的意思 |
| （新增）只读断言 | 断言里不再修改 wrap 尺寸：初版曾用「压矮 wrap 制造溢出」的写法，**触发布局递归导致进程 abort**（exit 134）。已改为纯只读，如实记录这次失败 |

## 5. 结果

`np web: 228 checks, 0 failures`（此前 227 PASS / 1 FAIL）。

## 6. 如实挂账

1. **溢出分支没有被夹具直接钉住**：现有夹具内容放得下，`overflow` 分支只在自洽断言里间接约束；
   要真正双向钉住需要一份「卡片高度可调」的夹具（或把 wrap 压矮的安全排版入口），本轮未做。
2. 拇指宽度固定 6pt（web 由系统滚动条决定，约 6~8）；沿用既有实现，未改。
3. 滚动条仍为自绘（非 NSScroller），与 web 的原生滚动条在动画细节上不同；本轮只对齐**占位**语义。
