## 一、拖动卡顿（第 1 条）

### 根因（代码级，行号）

`RLPEqualizerView.mm` 的 `curve.onDragBand` 回调里，每收到一个鼠标拖动事件就执行：

```objc
[s.bandTable reloadDataForRowIndexes:[NSIndexSet indexSetWithIndex:(NSUInteger)idx]
                     columnIndexes:[NSIndexSet indexSetWithIndex:0]];
```

两个问题叠在一起：

1. `reloadDataForRowIndexes:` 的语义是**重建这一行的 cell view**
   （每行含 NSTextField + NSPopUpButton）。鼠标拖动 60~120 Hz ⟹ 每秒上百次重建。
2. 传的列索引是 **0（段号列）**，增益列根本没被刷新 ——
   付了重建代价，界面上的数字还没变。

### 修复

新增 `- (void)refreshBandRowValues:`：只把**已存在**的 cell 的字符串改掉
（`viewAtColumn:row:makeIfNecessary:NO`，不新建 view、不重算行高），
并且正在编辑的那个框不抢（避免吞掉用户输入）。

### 判据 E17（先红后绿）

- 20 次拖动事件 → 恰好 21 次轻量刷新（1 次 mouseDown + 20 次拖动），
  **既不能 0（跳过刷新=界面不跟手），也不能 >21（还夹着别的重建路径）**
- 轻量刷新明显快于重建 cell（直接测耗时，这才是"卡顿"本身）
- 轻量刷新真的把新值写进了 cell（不是靠"不更新"换来的不卡）

> 红→绿实测：把 `reloadDataForRowIndexes` 放回热路径 ⟹
> `[FAIL] E17 … n=0`。

⚠️ **过程中发现一条无效判据并已替换**：最初写的是"cell 对象地址不变 ⟹ 无 reloadData"，
把旧实现放回去它**依然 PASS** —— NSTableView 会复用 cell 对象，地址不变证明不了没重建。
恒绿的判据只会制造"已验证"的假象，所以改成了计时。

## 二、推子板形态（第 2 条）

### 新增 `RLPEQFaderView`（独立视图，不与曲线混写）

为什么单独一个文件：曲线模式的坐标是 **对数频率 × 增益**（x 由频率决定）；
推子模式是 **等宽槽位 × 增益**（x 由段号决定，硬件 EQ 做法）。
两套几何混在一个 `drawRect` 里，拖拽命中与判据会互相污染。

按用户截图落地的形态：

| 元素 | 实现 |
|---|---|
| 每段一根竖直粗轨道 | `kTrackW = 7`，圆角矩形 |
| 白色圆形把手 | `kKnobR = 9`，白底 + 细描边 |
| 左边 dB 刻度 | ±24 / ±12 / 0 三档文字（不堆满数字） |
| **下面显示频率** | `kFreqRowH = 20` 的独立标签行，20/25/…/1K/1.25K/…/20K |
| **上面可输入 ±dB** | `kValueRowH = 28` 的 20 个 NSTextField，与推子一一对齐 |
| 当前调的那一段 | 轨道与把手用 accent 色高亮 |

- 默认显示推子板；工具栏「切换为曲线 / 切换为推子」可切回原曲线视图
  （**功能不删**，曲线仍是同一份数据的另一个视图）。
- 两者同址叠加（同一块位置，切换只改 `hidden`），不各占一行——
  语义相同，同时显示会把同一件事画两遍且卡片高度翻倍。
- 数据同源：`syncViewsFromBands` 一处把 `self.bands` 同步给两个视图。

### 判据 E16（先红后绿，逐条对应你提的三件事）

- 20 段、20 个频率标签**互不相同**、覆盖 20 Hz–20 kHz
- 绘图区下方留出标签行（`plotRect.origin.y > 5`）
- 每段上方都有输入框，且**都落在绘图区上方**（不是压在推子上）
- 20 个框里**都显示着数值**（不是空框）
- 输入 7.5 → 核心第 5 段真的 +7.5 dB
- 输入 99 → 被夹到 +24，且框里显示 24（不是原样留着 99）
- 向上拖第 10 段推子 → 只有第 10 段增益变大
- **先设频率再设增益，输入框也必须被填上数值**

> 红→绿实测：
> - 量程改回 ±18 ⟹ `E16 填 99 被夹到 +24 … gain=18.00` 红；
> - 输入框挪到底部 ⟹ `E16 这些输入框都排在绘图区上方 … above=0/20` 红；
> - 去掉短路分支里的 sync ⟹ `E16 先设频率再设增益 … filled=0/20` 红。

### 实现过程中真的踩到并修掉的两个显示 bug（都有判据兜住）

1. **20 个输入框全是空白**。
   `bandFreqs` 先到 → 建了 20 个空框；`bandGains` 后到 → 走"数量相等"短路分支，
   只 `layoutValueFields` 没 `syncFieldValues` ⟹ 永远空着。
   （光看"框存在、位置对"发现不了，是渲染成 PNG 才看出来。）
2. **离屏视图里一个框都不填**。
   `syncFieldValues` 用 `[[self window] firstResponder]` 判断"正在编辑"，
   没有 window 时是 `nil == nil` ⟹ 所有框都 `continue`。改成先判 window 存在。

## 三、±24 dB 量程（第 3 条）

原生 `RLPEQGeometry.mm` 原来写死 `RLPEQDbRange = 18.0`，与后端/web 不一致：

| 位置 | 值 |
|---|---|
| 后端解析钳位 `tools/rtaweb.cpp` | `clamp(g, -24.0, 24.0)` |
| 后端滤波设计 `src/dsp/peq.h` | `clamp(gainDb, -24, 24)` |
| web 表格 | `<input class=peqG min=-24 max=24>` |
| web 拖拽 | `Math.max(-24, Math.min(24, …))` |
| **原生（改前）** | **18.0 ← 错** |

后果：曲线画布拖到底只到 ±18，而参数表能填 ±24，两者对不上。

修复：`RLPEQDbRange = 24.0`；`drawRect` 里三处硬编码（`dbMax = 18.0`、`±18` 轴标、
`-12..12` 网格循环）全部改为由该常量推导，**不许再写死数字**。

> ±12 只是 web 那行"请复核"的软提醒，不是量程。

判据：`native_eq_geometry` E6–E9（顶部/底部/越界夹紧）与 E13（y=0.75 → +12 dB）
全部按 ±24 重算；E16 里再验一次"填 99 → 夹到 24"。
