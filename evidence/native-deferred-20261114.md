时间与风险权衡后，本轮只推进到 `#40`；下面两项**未改代码**，先把设计边界写清，避免下一轮盲改。

## #39 抽屉浮卡（web `#npData`）
- web：`#npData` 是**页面内浮层**（右栏滑入、宽度/圆角/阴影/动效都由页面 CSS 控制，
  `transform` 滑入 + 遮罩点击关闭）。
- 原生现状：`RLPCardController` + 系统浮卡（独立窗口/面板），动效与宽度不是 1:1，
  但功能等价（能看、能点、能关）。
- 为什么本轮不做：改成页内浮层要动导航层级与点击命中（`npClose`/面板开关同一 z 序），
  并要新增"点遮罩关闭"判据；这不是一行 CSS 能对齐的项，需单独一包 + 截图复核。
- 下一轮做法建议：在 `RLPNowPlayingViewController.view` 内加 `#npData` 子视图（web 宽度/圆角/阴影常量），
  用 `NSAnimationContext` 做滑入；判据量 **frame/圆角/阴影/滑入后位置**与遮罩点击关闭，不靠"看起来像"。

## #69 `.npchipwrap` 独立滚动
- web：右栏 `.npchipwrap` 是**独立滚动容器**（芯片卡多时只滚卡片区，栏头/分段不滚）；
  原生现状：芯片卡直接排在右栏面板的流式布局里，没有独立滚动容器（卡片少时视觉等价）。
- 为什么本轮不做：引入独立滚动必然新增 **第二个 NSScrollView**，直接撞上「单层滚动」判据
  （Lead 已明确提醒不要引入嵌套）；正确做法要么复用面板既有滚动（但那会让栏头一起滚，偏离 web），
  要么自绘滚动（像 `#npAnlBody` 那样用 `contentOffset` + 拇指），两者都要重排 rail 面板布局与判据。
- 下一轮做法建议（二选一，先写判据再动手）：
  1. **自绘滚动**（推荐）：`RLPRailChipsView` 内部 `contentOffset` + `drawRect` 拇指，
     不新增 NSScrollView；判据：可见 NSScrollView 数量不变、芯片滚动时栏头 y 不变、拇指不压卡片圆角；
  2. 复用面板滚动：接受"栏头一起滚"，但需在证据里明确偏离 web，并改现有 rail 判据。
